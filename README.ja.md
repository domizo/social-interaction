# Social Interaction Lab

**いいね・保存・共有の見た目と動きを、使われる場面で選び、React の実装へ。**

フィード・記事・チャットの操作 UI を作る開発者やデザイナーのための Studio です。サンプル画面で操作を試し、見た目や動きを調整。選んだ設定を保存して、React コンポーネントとして持ち帰れます。

[English](README.md) · [ローカルで試す](#ローカルで試す) · [React に組み込む](#react-に組み込む)

同じ設定をフィード・記事末尾・チャットで試して、それぞれの画面との相性を確かめられます。この画像は場面プレビューと設定欄で、アイコンの選択欄はその下にあります。[モバイル・日本語の実画面](docs/screenshots/studio-context-mobile-ja.png)も参照できます。画像は実ブラウザーでのキャプチャです。動きそのものは静止画では確認できません。

## 画面で選び、設定とコードを持ち帰る

1. **場面と操作を選ぶ。** サンプル画面を切り替え、「試すアイコンを選ぶ」で1〜12種類の操作を選択します。「前へ／後ろへ」で順番も調整できます。選んだ操作と順序は、場面プレビュー、見た目・動きの比較、デザインレンズ、状態の見本、プリセット、生成コードに反映されます。時間軸でも、選んだアイコンから観察する対象を切り替えられます。
2. **画面を見ながら調整する。** 見た目、余白、アイコンサイズ、線幅、動きを変え、ラベル付き／アイコンのみの表示を試します。EN/JA の名前は「操作とラベル」で編集し、保存や書き出しの前に「ラベルを適用」を押してください。
3. **あとで戻れる設定を残す。** このブラウザーに名前付きプリセットを保存するか、設定 JSON をダウンロードして再利用します。操作の順序、両言語のラベル、表示方法、見た目と動きの設定をまとめて保持できます。
4. **動く React の土台を持ち帰る。** 「React をコピー」または「TSX をダウンロード」で、設定を反映した `SocialActions.tsx` を取得します。状態を管理するトグル、ローカル入力フォーム、キーボード対応の共有メニュー、任意の `onCommand` コールバックを含みます。下の手順でパッケージを導入し、生成したコンポーネントを表示できます。コピーに失敗した場合は、選択可能なコードを表示します。

操作や通信はローカルのシミュレーションです。チャットの回答は固定のサンプルで、SNS・AI サービスには接続しません。

## こんな判断に使えます

### その画面に合う組み合わせを探す

記事末尾のコンパクトな操作列や、コミュニティ向けの表情のある操作を試せます。デザインレンズでは、余白・アイコンサイズ・線幅の1項目だけを変えて比較できます。操作領域、アイコン枠の中心、同じ行の横方向の間隔を表示し、何が変わったかを確かめます。比較時は左右の操作状態もそろえてください。美しさやアクセシビリティを採点する機能ではありません。

### 動きの気になる瞬間を止めて見る

時間軸で一時停止、スクラブ、低速再生、コマ送りを使い、選んだアイコンの動きを観察できます。操作時と同じ再生エンジンを使うため、実際の動きの計画を確認できます。時間や強さを調整したら、場面プレビューに戻って試せます。動きを抑える設定では、アイコンは静止表示になります。

### 通信をつなぐ前に、待ち時間や失敗時の見え方を比べる

非同期比較は、選択した操作セットとは独立した「いいね」と「保存」の実験です。押した直後に表示を変える楽観的更新と、成功してから変える方式を比較し、失敗・再試行・中止を試せます。表示値と確定値を分けて示すため、結果がまだ決まっていない間に何を伝えるかを検討できます。実際のバックエンド接続や性能測定を行う機能ではありません。

## ローカルで試す

Node.js 22.12 以上の 22 系、24 系、26 系と npm が必要です。

```sh
npm ci
npm run dev
```

Vite が表示するローカル URL を開いてください。アカウントや API キーは不要です。プレイグラウンドとライブラリをビルドするには、次を実行します。

```sh
npm run build
```

サイトを `dist/`、ESM ライブラリを `package/`、インストール用のアーカイブを `public/downloads/` に生成します。

## React に組み込む

プレイグラウンドから `social-interaction-lab-react-0.4.2.tgz` をダウンロードするか、`npm run build:package` で生成します。アーカイブを組み込み先の React プロジェクトへコピーし、そのプロジェクト内でインストールしてください。

```sh
npm install ./social-interaction-lab-react-0.4.2.tgz
```

npm レジストリには公開していない private アーカイブです。React 18.2 / 19 が peer dependency として必要で、ESM のみに対応します。CSS は明示的に読み込みます。

Studio で選んだ設定を使う場合は、生成コードを `SocialActions.tsx` として保存し、表示します。

```tsx
import SocialActions from './SocialActions';
import '@social-interaction-lab/react/styles.css';

export default function App() {
  return <SocialActions />;
}
```

個別の部品を組み合わせることもできます。

```tsx
import { useState } from 'react';
import { LikeButton } from '@social-interaction-lab/react';
import '@social-interaction-lab/react/styles.css';

export function PostLike() {
  const [liked, setLiked] = useState(false);
  return (
    <LikeButton label="いいね" selected={liked} variant="soft"
      onClick={() => setLiked(value => !value)} />
  );
}
```

生成コードにはローカルのポップアップ実装を含みます。一方、個別部品の CommentButton・QuoteButton はダイアログ、ShareButton はメニューを開くことを支援技術に伝えますが、ポップアップ自体は作りません。個別部品を使う場合は、対応するポップアップ、フォーカス移動・復帰、キーボード操作、`aria-expanded` / `aria-controls` を利用側で実装してください。動くローカル実装例は `src/app/LiveActions.tsx` にあります。

## 対応範囲と保存されるもの

- **アプリへの組み込み:** 生成コードには、選んだ操作と順序、ラベル、表示方法、トークン、動きを含みます。Studio の設定画面、記事・チャットのサンプル本文、時間軸、非同期比較は出力しません。`onCommand` は同期の通知コールバックです。実際の通信・永続保存・権限・エラー処理は利用側で実装します。
- **その場の操作状態:** トグルのオン／オフ、下書き、シミュレーションの処理状態は、画面を表示している間だけ保持し、再読み込みで消えます。アカウント連携、アクセス解析、SNS・AI 接続、投稿はありません。
- **再利用する設定:** 名前付きプリセットは最大20件で、このブラウザーの localStorage に保存します。クラウド同期や自動保存ではなく、再読み込み後は選んで読み込みます。削除するかブラウザーのデータを消すまで残ります。設定 JSON はスキーマ v1・最大64 KBで、全項目の検証に成功した場合だけ適用します。不正な入力で現在の設定を変更しません。
- **保存やコピーの失敗:** 保存領域を使えない場合はエラーを示し、保存成功とは表示しません。不正な保存済みデータは、明示的に消去するまで残します。コピーに失敗した場合は、コードを選択できる形で表示します。
- **書き出しの境界:** プリセットと生成コードには操作の選択を保持しますが、トグルのオン／オフ、下書き、処理状態、手動の動き抑制スイッチは含みません。生成コードは OS の動き抑制に対応します。`presentation` がない旧スキーマ v1 のプリセット／JSON は、ラベル付きで読み込みます。

検証条件、書き出し範囲、観察の進め方は [Studio ガイド](docs/STUDIO.md)を参照してください。

## ライブラリの仕様

### 操作カタログ

- 選択状態を持つ制御トグル: `LikeButton`（いいね）、`BookmarkButton`（ブックマーク）、`NoteButton`（メモを保存）、`StarButton`（スター）、`BellButton`（ベル）
- コマンド: `CommentButton`（コメント）、`ShareButton`（共有）、`QuoteButton`（引用）、`RepostButton`（リポスト）、`SendButton`（送信）、`SparklesButton`（きらめき）、`ReactionButton`（リアクション）
- `ActionButton` と装飾用 SVG の `ActionIcon` で、同じ12種類の `SocialAction` を使えます
- `socialActions` / `toggleActions` / `isToggleAction` と EN/JA の `actionLabels` を公開し、カタログの実装に再利用できます

トグルの `selected` は `aria-pressed` に対応し、選択前後でアクセシブル名を変えません。`NoteButton` は付箋の形をした保存操作の別案です。プレイグラウンドでのラベルは「メモを保存」/ “Keep note” で、文章を入力するエディタではありません。Sparkles に AI 機能はなく、リポストや送信を含むすべての操作はローカルのシミュレーションです。

### アイコンのみで表示する

`presentation="icon-only"` は見えるラベルと件数を隠します。必須の `label` は固定のアクセシブル名と標準の title ヒントに使い、指定した件数はアクセシブルな説明として残します。この prop は任意で、初期値は `"labelled"` です。表示方法だけを変え、トグル／コマンドの動作、フォーカス、最小操作領域、動きは変更しません。

```tsx
<LikeButton label="いいね" presentation="icon-only" count={12} selected={liked}
  onClick={() => setLiked(value => !value)} />
```

既存の `showLabel={false}` はラベルだけを隠す互換動作を保ち、ラベル付き表示なら件数は表示されます。標準の title ヒントの表示はブラウザーに依存し、タッチ操作での発見を保証しません。意味が伝わりにくいアイコンには見えるラベルを使ってください。

### アイコン自体を動かす

見た目の variant とは別に、`iconMotion="pulse"` / `"spring"` / `"trace"` / `"gesture"` / `"cartoon"` を選べます。`"none"` ならアイコンの動きを止めます。「動き」セクションで選んだ操作を5つの表現で比較し、時間・強さ・パーツの時間差を調整できます。別の12枚のカタログで、選んだ動きを全アイコンに適用して確認できます。カタログのプレビューはポップアップや外部サービスを起動しません。一括再生や処理中プレビューができ、選んだ動きはローカル操作にも反映されます。

```tsx
<LikeButton label="いいね" selected={liked} iconMotion="cartoon"
  motionTokens={{ duration: 560, intensity: 1, stagger: 60 }}
  onClick={() => setLiked(value => !value)} />
```

cartoon では、ハートの小刻みな震えと拡大しながら消える輪郭を表現します。コメントは指定時間の最初の75%で、左下の小さな円から膨らみながら上がり、頂点で基本の吹き出しが完成します。最後の25%で落下し、着地時につぶれ、小さく跳ね返って静止します（初期値560 msでは420 ms＋140 ms）。リポストは従来どおり、元の長方形の経路に沿って一定長の矢印本体が移動します。他のアイコンも操作に合わせた動きを SVG 自体で表現します。心地よさの説明は文脈の中で検証する仮説です。

アイコンの時間は 0–1600 ms、強さは 0–2、パーツの時間差は 0–160 ms。開始時の動きは成功を意味しません。処理中はゆっくり反復し、静止した点と状態説明を残し、cartoon の追加バーストは表示しません。OS 設定と `reducedMotion` に対応し、動きがなくても状態を伝えます。装飾エフェクトも再生単位で中止され、操作領域の大きさは変わりません。詳しくは[動きの API・意図・制約](docs/MOTION.md)を参照してください。

Studio の時間軸では選択した操作のアイコンを観察できます。単独の `ActionIcon` SVG を `createGlyphTimeline` が専有して再生します。動作中の `ActionButton` 内の SVG には接続しないでください。合計時間にはパーツの時間差も含みます。公開 API は [API ガイド](docs/API.md)を参照してください。

### 状態と非同期処理

`useAsyncAction<T>()` は run / cancel / reset と status / value / error を返します。1つの hook は1つの操作を所有し、処理中の重複開始を無視します。中止・アンマウント後の古い応答は反映しません。AbortSignal を受け取る処理を渡してください。UI の中止がサーバー側の変更を取り消すわけではありません。

## 設計と運用

- `src/lib/tokens.ts` を共通のトークン定義にし、部品・見本・調整 UI・DTCG 出力に使います
- minimal / soft / solid / spring の4種類。印象の説明は、万人に通じる美の法則ではなく検証する仮説です
- アイコンの大きさと線幅は独立。操作領域の最小44 px は設計上の選択です
- WCAG 2.2 の AA 2.5.8 は最小24 × 24 CSS px で、規定の例外があります
- DTCG 2025.10 はコミュニティグループの仕様で、W3C 勧告ではありません
- 動きを抑える OS 設定に対応。アクセント色変更時はコントラストを再確認してください
- [API](docs/API.md)、[設計](docs/DESIGN.md)、[アクセシビリティ](docs/ACCESSIBILITY.md)、[貢献手順](CONTRIBUTING.md)、[変更履歴](CHANGELOG.md)

## 検証と配布

```sh
npm run check
npm test
npm run build
npm run verify:consumer
npm run verify:generated
npm run verify:archive
```

`verify:archive` は Git HEAD が必要で、そのコミットに記録されたファイルだけを使って検証します。

`verify:consumer` は新しい外部プロジェクトに tarball をインストールし、厳密な NodeNext 型検査、ESM の実行時 import、CSS を確認します。`verify:generated` はビルド済み tarball と既存の依存関係を使い、EN/JA・ラベル付き／アイコンのみ・全操作・単独操作・最大長ラベルを含む生成 TSX を型検査します。ブラウザー検証用に独立した生成コンポーネントのページもビルドします。この QA ページは公開対象に含めません。CI の設定は `.github/workflows/quality.yml` にあります。コマンドや CI の定義が存在することと、実行済み・成功済みであることは別です。ブラウザー検証の実施範囲と結果は [QA 記録](https://github.com/domizo/social-interaction-lab/blob/main/docs/QA.md)を参照してください。

private ソースと private デモです。公開ライセンス決定までは UNLICENSED。npm には公開していません。DOM テストはブラウザのレイアウトや実際の支援技術による確認を代替しません。
